# 衍灵内核框架 — 灯塔沟通手册

> 本文档供你与灯塔沟通时参考，帮助对方快速理解衍灵是什么、能做什么、如何与现有体系整合。

---

## 一、衍灵是什么

衍灵是一个 **通用 AI 自我进化系统内核**。本质上是一个可嵌入的智能决策引擎，以固定频率循环运行"感知→认知→行动→进化"四阶段流程。

```
每个 Tick（心跳周期）:
  感知 (Perceive) → 收集传感器/外部输入
     ↓
  认知 (Cognize)  → 规则匹配 或 LLM 推理，产生决策
     ↓
  行动 (Act)      → 执行决策，调用具体适配器
     ↓
  进化 (Evolve)   → 分析结果，提取模式，积累经验
```

**定位：** 衍灵不替代现有系统，而是作为底层驱动层嵌入到流程中。可以理解为给现有系统装上一个"会自我优化的决策大脑"。

## 二、核心能力

### 2.1 双模式认知

| 模式 | 依赖 | 适用场景 |
|------|------|---------|
| **规则驱动** | 无外部依赖 | 离线/本地，低延迟，确定性输出 |
| **LLM 驱动** | DeepSeek API / oMLX 本地模型 | 需要推理、理解复杂上下文 |

两种模式可以共存，按需切换。

### 2.2 分层记忆系统

模仿人脑记忆模型，分三层：

```
工作记忆 (Working Memory)
  └── 当前 tick 的快照，容量有限，随 tick 滚动
      ↓
短期记忆 (Short-Term Memory)
  └── 最近 N 条记录的摘要，TTL 过期淘汰
      ↓
长期记忆 (Long-Term Memory)
  └── 重要经验、失败模式，持化到磁盘 (JSON/Supabase)
```

### 2.3 进化系统（核心差异化）

每次 tick 后自动执行轻量学习：

- **性能追踪** — 滑动窗口记录成功率、延迟、token 消耗
- **失败分析** — 自动识别失败行动并记录原因
- **模式提取** — 从重复失败中提取可复用的模式
- **深度进化**（需 LLM）— 定期分析运行趋势，自动调整策略参数

进化是可逆的：每次调整前保存快照，支持回滚。

### 2.4 边界控制系统

行动执行前经过边界检查，支持：

- 速率限制（令牌桶，每分钟/每小时配额）
- 操作范围限制（只能执行允许的行动类型）
- 时间窗口限制（只能在指定时间段行动）

### 2.5 插件系统 + 事件总线

内部通过事件总线通信，插件可扩展任意环节：

- 感知插件（新的输入源）
- 行动插件（新的输出能力）
- 进化插件（扩展自我改进策略）
- 服务插件（后台定时任务）

### 2.6 Web 可观测面板

- 实时仪表盘：Tick 计数、成功率、延迟、引擎状态
- 记忆检视：工作记忆 / 短期 / 长期三层数据可视化
- 进化看板：性能趋势、模式库、策略调整历史
- JSON API，支持 HTMX 自动刷新

## 三、当前运行状态

运行在 WSL2 园丁环境，端口 8764。

**正在进行的进化验证实验：**
- 模拟传感器（温度/振动/压力）持续产生数据

## 四、与现有体系的整合点

### 4.1 与园丁 (auto-content) 整合

园丁是目前 7×24 运行的自主运维系统，衍灵可以：

**1. 进化优化运维策略**
   - 园丁产生告警 → 衍灵分析告警模式 → 识别重复失败 → 自动调整巡检频率/阈值
   - 例：某端口频繁超时 → 进化引擎识别模式 → 调整边界规则减少检测频率 → 降低误报

**2. 记忆驱动的告警分析**
   - 园丁的告警历史导入衍灵的长期记忆 → 新告警产生时自动关联历史模式
   - 例：磁盘告警 → 衍灵检索到上次类似情况的处理方式 → 推荐操作

**3. 双引擎协同**
   - 园丁负责执行（采集、发布、通知）→ 衍灵负责决策（分析、优化、进化）
   - 衍灵目前是独立运行，可嵌入到园丁的任意环节

### 4.2 与灯塔的整合

灯塔（塔主）是跨设备协调中心，衍灵可以：

**1. 场景策略下发**
   - 灯塔定义场景规则 → 下发给衍灵执行 → 衍灵运行结果回传

**2. 分布式进化**
   - 多节点衍灵各自运行 → 进化经验汇总到灯塔 → 灯塔分发优化后的策略

**3. 统一监控**
   - 衍灵面板可作为节点状态的可视化入口

### 4.3 整合路线图

```
短期（当前已完成）：
  └── 衍灵独立运行，Web 面板可观测
  └── 进化验证实验进行中

中期（需灯塔沟通后）：
  └── 园丁 → 衍灵数据通道（告警导入、模式分析）
  └── 衍灵 → 园丁策略输出（优化建议、阈值调整）
  └── 统一事件总线打通

长期：
  └── 多节点衍灵集群
  └── 灯塔统一下发场景策略
  └── 跨设备进化经验共享
```

## 五、技术要点（供参考）

| 概念 | 说明 |
|------|------|
| **Tick** | 衍灵的主循环心跳周期，默认 2 秒 |
| **Percept** | 感知数据单元，含来源、类型、数据、时间戳 |
| **Action** | 行动指令，含类型、目标适配器、参数 |
| **CognitionResult** | 认知输出，包含决策列表 |
| **EvolutionStep** | 单次进化步记录，含观察、调整、结果 |
| **Checkpoint** | 长期记忆持久化快照 |
| **BoundaryRule** | 边界规则，在行动执行前拦截违规操作 |
| **Plugin** | 插件，通过事件总线与内核松耦合交互 |
